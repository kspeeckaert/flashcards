# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A flashcard web app, delivered as a Progressive Web App (PWA) on GitHub Pages: <https://kspeeckaert.github.io/flashcards/flashcards.html>. It works offline after the first visit. The app code has no build step. A small build script copies the libraries into `vendor/` and writes the offline file list into `sw.js` (see "Service worker and build script").

A companion tool `img-to-md.html` converts images to base64 and generates the reference definitions (`[key]: data:image/...`) for image-enabled decks.

## File structure

```
js/pwa.js               Shared by both pages: version footer, service worker registration, update banner

img/icons.svg           SVG sprite (UI icons)

img/icon.svg            App icon, source of img/icons/*.png

css/img-to-md.css       Styles of the helper
js/img-to-md.js         Logic of the helper
vendor/                 Generated by scripts/build.js: marked, DOMPurify, KaTeX, marked-katex-extension, Mermaid, fonts. Do not edit
scripts/build.js        Build script (Bun or Node.js)
package.json, bun.lock  Pinned library versions (devDependencies)
sample.md               Example deck
```

## Development

Serve locally and open `flashcards.html` in a browser:

```
python3 -m http.server 8080
```

On `localhost` and `127.0.0.1`, `js/pwa.js` does not register the service worker, so edits show after a normal reload. Add `?sw` to the URL to test offline mode locally.

The app loads no files from other websites. All libraries and fonts come from `vendor/`, which `scripts/build.js` writes from `node_modules/`. Do not add CDN links. To add or upgrade a library, change `package.json`, run `bun install`, add the files to `LIBRARIES` in `scripts/build.js` if needed, and run `bun run build`.

## Service worker and build script

`sw.js` precaches every file in its `PRECACHE_URLS` list on install, in a cache named `flashcards-<APP_VERSION>-<BUILD_HASH>`, and serves those files cache-first. The block between `// BEGIN PRECACHE` and `// END PRECACHE` is generated. Do not edit it by hand.

Rules for every change:

- After you change, add, or remove any file in `css/`, `js/`, `img/`, or an HTML page, run `bun run build`. Without it, the precache list or the hash is out of date, and installed apps do not update or break offline.
- After you change the version in `js/version.js`, run `bun run build`. The script copies the version into `sw.js`.
- `bun run check` reports whether `vendor/` and `sw.js` are up to date (exit code 1 if not) and changes nothing.
- Commit `vendor/` and `sw.js` with the change. GitHub Pages serves the repository as it is.

Design decisions:

- `sw.js` does not use `importScripts()`. Browsers can serve imported scripts from their HTTP cache, which gave a stale version. The build script writes `APP_VERSION` into the block instead.
- The install step requests each file with `cache: 'reload'`, so a new version never stores stale files from the browser's HTTP cache. A local test with `python3 -m http.server` showed this problem without it.
- A new service worker waits. `js/pwa.js` shows an update banner, and the "Reload" button sends `SKIP_WAITING`. The page reloads on `controllerchange` only after that click, because `clients.claim()` also fires `controllerchange` on the first install.
- Offline navigations to an unknown URL inside the scope get a redirect to `flashcards.html`, not the page itself, so its relative links keep working.
- `vendor/` holds only `.woff2` fonts. KaTeX CSS lists woff2 first, so the `.woff` and `.ttf` files are never requested. Lora and DM Sans use the latin and latin-ext subsets only.

## Script loading and initialisation order

Understanding load order is critical — getting it wrong causes silent failures (listeners never registered, `marked` not yet available, etc.).

### How scripts are loaded

All five `<script>` tags in `flashcards.html` carry `defer`:

```html
<script defer src="vendor/marked/marked.umd.js">      <!-- 1 -->
<script defer src="vendor/dompurify/purify.min.js">   <!-- 2 -->
<script defer src="js/version.js">                    <!-- 3: APP_VERSION -->
<script defer src="js/pwa.js">                        <!-- 4: footer, service worker -->
<script defer src="js/flashcards.js">                 <!-- 5 -->
```

`js/pwa.js` runs before `js/flashcards.js`, so an error in the app code does not stop the service worker registration.

`defer` means: **download in parallel, execute in order, after HTML parsing is complete**. By the time any deferred script runs, the full DOM is available. Scripts execute strictly in the order they appear in the HTML.

### What this means in practice

| When | What is guaranteed |
|---|---|
| `flashcards.js` starts executing | DOM is fully parsed; `marked` and `DOMPurify` have already run |
| Any top-level statement in `flashcards.js` | Safe to call `marked`, `DOMPurify`, and `document.getElementById(...)` |
| `DOMContentLoaded` event | Already fired before any deferred script runs — **do not use it inside `flashcards.js`** |

### The `DOMContentLoaded` trap

Because `DOMContentLoaded` fires *before* deferred scripts execute, registering a listener for it inside `flashcards.js` is a no-op — the event has already passed. Any code placed inside such a listener will never run.

**Wrong:**
```js
document.addEventListener('DOMContentLoaded', () => {
  marked.use({ breaks: true }); // never called
  renderDeckList();              // never called
});
```

**Correct** — just write top-level code; `defer` provides the same guarantee:
```js
marked.use({ breaks: true }); // runs after marked.js, with DOM ready
renderDeckList();
```

### KaTeX — lazy-loaded on demand

KaTeX JS (~270 KB) is **not** in the HTML. It is injected dynamically by `loadKaTeX(cb)` in `flashcards.js` from `vendor/katex/` the first time a card containing `$` is rendered, followed by `vendor/marked-katex-extension/index.umd.js`. The extension's UMD build reads the global `katex` when it loads, so the order matters. The CSS is loaded unconditionally from `<head>` (small, non-blocking). The service worker precaches the KaTeX files, so math also works offline on a device that never showed math online.

Math is rendered **inside** `marked.parse()` by `marked-katex-extension`, not after it. Markdown therefore never changes the LaTeX source (backslash escapes such as `\,` and `\{`, `*`, `_`). Do not add KaTeX auto-render back: it runs after marked, when the source is already changed.

```
setCardContent() gets text with a $ and KaTeX is not ready
  → renders the text without math (marked + DOMPurify + fitText)
  → loadKaTeX() injects <script> for katex.min.js
      → on load, injects <script> for marked-katex-extension
          → marked.use(markedKatex({ throwOnError: false }))
              → calls all queued callbacks
                  → setCardContent() renders the text again, if no newer text was set on that face
```

Subsequent calls to `loadKaTeX()` are immediate no-ops if KaTeX is already loaded, or queue the callback if loading is still in progress. If a script fails to load, the queue is dropped (math stays as text) and the next call tries again.

### Mermaid — lazy-loaded on demand

Mermaid (`vendor/mermaid/mermaid.min.js`, ~5.5 MB, UMD build that sets `globalThis.mermaid`) is **not** in the HTML. `loadMermaid()` injects it the first time a diagram must show, calls `mermaid.initialize()` once, and returns a promise for the `mermaid` object. A failed load resets the promise, so the next diagram tries again. The service worker precaches the file.

`mermaid.initialize()` settings:
- `startOnLoad: false` — the app calls `mermaid.render()` itself
- `securityLevel: 'strict'` — Mermaid sanitizes labels and disables click handlers
- `suppressErrorRendering: true` — a syntax error throws instead of inserting an error diagram
- `theme: 'base'` with `themeVariables` read from the CSS variables (`--accent`, `--ink`, `--font-ui`, …), so diagrams match the app

### Summary diagram

```
HTML parse completes
    │
    ├─ marked.umd.js executes
    ├─ purify.min.js executes
    ├─ version.js executes
    ├─ pwa.js executes          ← version footer, service worker registration
    └─ flashcards.js executes   ← all top-level code runs here; DOM and deps ready
         │
         └─ (later, on first math card) loadKaTeX() → katex.min.js → marked-katex-extension
```

## Architecture

### Screens

Four `<div class="screen">` elements are shown/hidden via `showScreen(id)`:
- `screen-load` — file upload / saved deck library
- `screen-select` — section picker and study options
- `screen-study` — active card study session
- `screen-done` — results and replay options

### Drag-and-drop

`dragover` and `drop` are suppressed on `document` globally (prevents the browser navigating away on an errant drop). `loadFile` is only called when `screen-load` is the active screen — drops on other screens are silently discarded.

### Markdown format

Cards are parsed by `parseMD()`:
- `#` heading → deck name
- `##` heading → section title
- `###` heading → card front
- Lines after `###` → card back, unless the card has a `---` line: then the lines between `###` and the first `---` are extra front text and media, and the lines after it are the back
- Both sides support Markdown and LaTeX math

`parseMD()` runs two passes. Pass 1 finds fenced code blocks (``` or ~~~, CommonMark closing rules) and collects reference definitions `[label]: destination` from the whole file (outside fences) and removes them. Pass 2 reads headings, the `---` separator, and card lines. Lines inside a fence are never read as headings, separators, or definitions. An unclosed fence produces a warning.

All warnings (skipped cards, `####` headings, unknown or unused image labels, non-data image URLs, more than one media item on a side, the old image format) are collected and shown in one `alert()` after the parse.

Math is rendered by KaTeX through `marked-katex-extension`, inside `marked.parse()`, before DOMPurify:
- `$...$` → inline math. The opening `$` must be at the start or after a space, and the closing `$` before whitespace, `.,:?!` (or their full-width forms), or the end of the line. So `$5 and $10` stays text, and so does `($x$)`
- `$$...$$` on one line → display math
- `$$` on its own line, the formula, `$$` on its own line → display math (block rule)
- `throwOnError: false` — an invalid formula renders as a red `.katex-error` span with the source
- DOMPurify removes the MathML `<annotation>` element from the KaTeX output. The visible HTML rendering is not affected

#### Media: images and diagrams

Each side of a card has at most one media item, stored as `card.frontMedia` and `card.backMedia`:
- `{ type: 'image', src, alt }` — from `![alt][label]`, `![label][]`, `![label]` (only if the label has a definition), or inline `![alt](data:image/...)`
- `{ type: 'diagram', code }` — from a fenced block with info string `mermaid`
- `null` — no media

Rules:
- Labels match the CommonMark way: case-insensitive, runs of whitespace count as one space (`normalizeLabel()`). The first definition of a label wins.
- Only `data:image/` destinations are accepted. Other URLs give a warning, because the app must work offline.
- The parser removes the media markup from the line and keeps the rest of the line. Image markup inside an inline code span stays as text.
- A second media item on the same side gives a warning and is dropped.
- A card is skipped only if its back has neither text nor media.
- The old format (YAML `images:` frontmatter and `<!-- img:key -->`) is not supported. A `<!-- img:... -->` comment produces one warning and is removed.
- Use `img-to-md.html` to convert image files to base64 definitions.

### Key functions

- `parseMD(text, filename, { warn = true })` — parses markdown into `{ filename, name, sections: [{title, cards:[{_id, front, back, frontMedia, backMedia}]}] }` (see "Markdown format"). `front` is the heading plus any extra front text. Each card receives a stable `_id` (integer) assigned during parsing — used for missed-card tracking to avoid reference-equality fragility. `####`+ headings trigger a user-facing warning and are skipped. `###` cards that appear before any `##` section are silently grouped under a synthetic `{ title: 'Cards' }` section — this is intentional to tolerate decks without explicit sections. `loadDeckById()` passes `warn: false`, because the warnings already showed when the deck was loaded from its file.
- `setCardContent(el, text)` — renders markdown (and math, once KaTeX is loaded) into a card face via `renderMarkdown()`: `marked` + `DOMPurify`, then `fitText()`; wrapped in try/catch, falls back to plain text on error. If the text contains `$` and KaTeX is not loaded yet, it loads KaTeX and renders again; a sequence number in `el.dataset.renderSeq` stops that second render if newer text was set on the face
- `fitText(el)` — binary-search font-size (11 px minimum) to fit card content without overflow. Runs the search on an off-screen, fixed-position clone (without its `id`), so each read forces a layout of the small clone only, and applies the result to the live element in a single write. It uses `el.clientWidth`, not `getBoundingClientRect()`, because the bounding box includes CSS transforms and is narrower during a flip or a swipe. KaTeX scales proportionally with inherited `font-size` (`1em`) so no special treatment is needed for display math.
- `refitCardText()` — fits both faces again, at most once per animation frame, and only while the study screen is visible. A `ResizeObserver` on `.card` calls it when the card width changes (window resize, rotation). `document.fonts.ready` and the `loadingdone` event call it when a web font finishes loading. The card has a fixed height and fills the width, so fitting the text cannot trigger the observer again.
- `renderCard()` — updates the DOM for the current card. Uses `faceText()` so that a side with media but no text shows "see image" or "see diagram". Calls `updateMediaPanel()`
- `updateMediaPanel()` — shows the media of the visible side in the media panel (front before the flip, back after it; swapped in reverse mode), or hides the panel. Called by `renderCard()` and `flipCard()`
- `commitAnswer(hit)` — records the answer, triggers swipe/fly animation, advances to next card
- `showScreen(id)` — switches the active screen; clears the media panel (`clearMediaPanel()`) when leaving the study screen

### State

All state is module-level variables (`activeDeck`, `cardIndex`, `hits`, `misses`, `isFlipped`, `isReversed`, `prevState`, etc.). There is no framework.

`missedCards` stores card `_id` integers (not card objects) to avoid reference-equality fragility across shuffled copies. "Study missed" resolves them back to card objects via a `Set` lookup against `lastDeck` (the cards of the last round). "Study again" uses `selectionDeck` (the cards of the selected sections), so it returns to the full selection after a missed-cards round.

`buildSelectScreen()` resets shuffle to on and reverse to off for each newly loaded deck. "Change sections" keeps both.

`deckSwipeRevealed` is a module-level `Map<deckId, bool>` shared between `initDeckSwipe()` and the global `touchstart` handler so both the DOM transform reset and the logical revealed state stay in sync. `renderDeckList()` clears it, because the rebuilt items start closed.

The undo feature supports a single level of undo only — `prevState` captures the state before the last committed answer (`null` means nothing to undo), and undoing restores it. This is by design: multi-level undo adds complexity with little practical benefit for a flashcard study flow. Undo always returns the card face-up — intentional. After the last card, the done screen shows "Undo last answer" (`#btn-undo-last`) while `prevState` is set; it returns to the study screen and calls `goBack()`.

`flipCard()` does nothing while `isAnimating` is true (the fly-off after an answer).

`FLIP_MS` comes from the CSS variable `--flip-ms`, which also sets the `.card` transition. Change the flip duration only there.

### Persistence

Saved decks live in IndexedDB, database `flashcards`, with two object stores keyed by deck id:

- `decks` holds the metadata for the deck list: `{ id, name, sections, cards, createdAt, hash }`. `hash` is the SHA-256 of the raw markdown (`deckHash()`). It is `null` without `crypto.subtle` (plain HTTP on a LAN address), and decks saved before version 1.50 have none.
- `bodies` holds the raw markdown, including embedded images: `{ id, raw }`.

The deck list reads only `decks`. `getDecks()`, `getDeckRaw()`, `putDeck()`, and `removeDeck()` are async. `putDeck()` resolves only after the transaction completes.

The save switch saves at once: its click calls `saveDeck()`. `saveDeck()` sets `hasSavedCurrentDeck` before the write and resets it if the write fails. If a saved deck has the same `hash`, it writes nothing. `loadFile()` also looks up the hash and marks the deck as saved if it finds one. `refreshSaveToggle()` shows the state: on, disabled, and "(saved in this browser)" for a saved deck; off and disabled with "(storage not available)" without IndexedDB. The first successful save calls `navigator.storage.persist()`. It is not called at startup, because Firefox shows a permission prompt. The storage meter uses `navigator.storage.estimate()`. If IndexedDB is not available, `saveBlocked` is true and the save toggle is disabled.

Versions before 1.43 saved decks in `localStorage` under the key `fc_decks`. The app does not read or migrate that key. Session state (score, position) is not persisted.

### Card content constraint

Card content must always be fully visible without scrolling. `fitText()` shrinks the font to make content fit within the fixed card height. When adding features that render into card faces, ensure the result still fits completely — do not allow vertical overflow or scrolling inside a card, nor clip the content.

### Media panel layout

The media panel (`#card-media-panel`) sits **below** `.answer-btns` in the DOM, outside the card flip mechanism. It holds `#card-image` and `#card-diagram`, and shows at most one of them. Key constraints:
- The panel shows the media of the visible side only, so back media never gives the answer away before the flip. If the visible side has no media, the panel is hidden. Nothing in the layout sits below the panel, so its height change on a flip moves nothing.
- The answer buttons use `opacity` only for their show/hide transition (no `translateY`) so they always occupy their layout space — this prevents the panel from shifting when the card is flipped
- Media is never shown inside the card faces
- `max-width: 100%` with `height: auto` preserves aspect ratio and prevents upscaling beyond natural size
- `#card-diagram` holds the SVG from `mermaid.render()`. `showDiagram()` inserts it with `innerHTML` and does not pass it through DOMPurify: the default DOMPurify profile removes `foreignObject`, which Mermaid uses for labels, and `securityLevel: 'strict'` already sanitizes the labels
- `mediaToken` increases on each `updateMediaPanel()` and `clearMediaPanel()` call. A render that finishes after the visible side or card changed is cached but not shown
- `diagramSvgCache` maps the Mermaid source to its SVG, so undo, reverse mode, and "Study again" do not render a diagram twice
- If Mermaid throws, the panel shows "This diagram has an error. Its source:" and the source in a `<pre>`
- The SVG scales down to the panel width (`max-width: 100%`) and never up
- The panel is cleared (`display: none`, `removeAttribute('src')`) when navigating away from the study screen — using `removeAttribute` rather than `src = ''` avoids a spurious request to the page URL

### Accessibility

- The card is `role="button"` with `tabindex="0"`. Enter (when the card has focus) and Space flip it. `startStudy()` moves the focus to the card.
- `updateFaceVisibility()` sets `aria-hidden` on the face that is not visible, so screen readers cannot read the answer before the flip.
- `setAnswerButtonsVisible()` sets `inert` on `.answer-btns` while they are hidden, so Tab cannot reach "Got it" or "Miss" before the flip.
- The shuffle, reverse, and save toggles are `<button role="switch">` elements. Always change them with `setSwitch(id, on)`, which updates `aria-checked` and the knob class together. The save switch gets the `disabled` attribute when the deck is saved or storage is not available.
- Section rows are `role="checkbox"` with `aria-checked` and `tabindex="0"`. Space and Enter toggle them. The hidden `<input type="checkbox">` inside each row still holds the state for `refreshCount()`.
- In the deck list, `.deck-item-content` is `role="button"` with `tabindex="0"` (Enter or Space opens the deck). The trash button has an `aria-label` with the deck name and shows on `:focus-visible`. The swipe-only `.deck-delete-reveal` button has `tabindex="-1"` and `aria-hidden="true"`.
- The global keydown handler ignores keys with Cmd, Ctrl, or Alt (browser shortcuts), and leaves Space and Enter to a focused button, link, or form field.
- `:focus-visible` shows a 2 px accent outline on every focusable element.

### SVG assets

- `img/icons.svg` — SVG sprite; all UI icons are referenced via `<use href="img/icons.svg#icon-name"/>`
- `img/watermark.svg` — decorative illustration loaded via `<img>` tag; fill colour is baked in as `#1e1c18` since `currentColor` does not propagate through `<img>`

### Versioning

The version is `APP_VERSION` in `js/version.js`, format `<major>.<minor>.<YYYYMMDD>`. Update it for each change, then run `bun run build`. `js/pwa.js` writes it into the `.version` footer of both pages, and the build script copies it into `sw.js`. Both pages share one version.

## img-to-md.html

Helper tool, part of the same PWA. It loads `js/version.js`, `js/pwa.js`, `css/pwa.css`, and the local fonts, but no other libraries. The wordmark at the top links back to `flashcards.html` (an installed app has no browser back button), and the start screen of the app links to the helper. Drop image files → generates one reference definition per image (`[key]: data:image/...`) and a `![alt][key]` snippet per image, with an alt text field.

### Key functions (`js/img-to-md.js`)

- `imageType(file)` — the MIME type of a file, from the file extension if the browser gives none. `processImage()` then also corrects the `data:` prefix that `FileReader` writes.
- `readFiles(files)` — validates type and deduplicates by filename (one alert for all unsupported files, one for all duplicates), then runs `processImage()` on all files with `Promise.allSettled()`. It adds the entries in the order the user chose the files and calls `renderList()` and `renderOutput()` once. A file that cannot be decoded gives an alert and is skipped.
- `processImage(file)` — returns `{ dataUri, width, height, note }`. SVG and GIF stay as they are. Other images are drawn on a canvas with the longest side at most `MAX_SIDE` (1200 px). `looksLikePhoto()` samples the pixels: no transparency and more than `PHOTO_MIN_COLORS` (4096) distinct colors means JPEG (`JPEG_QUALITY` 0.85), otherwise PNG. Safari cannot encode WebP from a canvas, so WebP is never an output. If the result is not smaller than the original data URI, the original is kept.
- `uniqueKey(base)` — derives a collision-free key from a filename; snapshots existing keys into a `Set` once before the loop to avoid repeated array mapping. Keys are compared in lower case, because Markdown labels are case-insensitive (`isDuplicateKey()` does the same).
- `snippetFor(entry)` — returns `![alt][key]`, with the key as alt text if the alt field is empty. Brackets are removed from the alt text.
- `copyText(text, btn)` — writes to clipboard and toggles a "✓ Copied" state on the button. Targets `btn.querySelector('span') || btn` for the label so SVG children on icon-bearing buttons are not clobbered.
- `renderList()` — rebuilds the image list UI from `entries`; wires key-input, alt-input, remove, and snippet-copy handlers.
- `invalidKeys` / `refreshCopyState()` — while a key is invalid, its snippet gets the `stale` class, its copy button and "Copy definitions" are disabled, and `#output-stale` explains why: the output still holds the last valid key.
- `esc(s)` — the same HTML escape function as in `js/flashcards.js` (`& < > " '`).
- `renderOutput()` — rebuilds the definitions `<pre>` block from `entries` and the total size in `#output-total` (the data URI length, which is what the deck stores); hides the panel when empty.

### Behaviour notes

- Dropping the same filename twice is detected and skipped with an alert — deduplication is by `filename`, not file content.
- The "Copy definitions" button in `img-to-md.html` wraps its label text in a `<span>` so `copyText` can update just the text without touching the adjacent SVG icon.
